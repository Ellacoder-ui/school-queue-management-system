# Staff Counter Exclusivity Migration

Migration `20261022001150_owner_remove_ineligible_counter_assignment.sql` (SHA-256 `5C47FE6F1245393E5104D87EC81CAE27C3FFED772CCD0F77E9E23B5239F46BA2`) adds the owner-only `queue_api.remove_ineligible_counter_assignment` RPC. It removes exactly one assignment belonging to a non-CASHIER or disabled account, refuses to remove an enabled CASHIER, and preserves the account, role, counter state, other assignments and ticket history. It depends on migration 011's owner authorization helper and is ordered before migrations 013 and 014 so it can resolve legacy rows before exclusivity constraints are installed.

The cleanup RPC migration was applied and tested only on disposable PostgreSQL cluster `7698728238191685666`; its SQL test passed 15 assertions for owner authorization, exact-row removal, cashier preservation, account-role preservation and idempotent replay. The retained cluster `7696959712798593061` has **not** received it. The Counter 2 pending reservation was canceled through the installed owner-authorized dashboard RPC at the user's direction; its active cashier remains assigned. Counter 5 still has an active CASHIER assignment and a STUDENT assignment. A separately confirmed attempt to remove only the STUDENT assignment through the existing `configure_counter` RPC was rejected, and no Counter 5 data changed. The new cleanup RPC is ready for separate review and approval before installation.

Migration `20261022001400_enforce_staff_counter_exclusivity.sql` (SHA-256 `033C0D006AC204EA2479767C8826A9927C64CB7D5225ADCE5D98B60A5BF2B124`) enforces one active cashier per counter and one counter per cashier, prevents active assignments from colliding with pending cashier reservations, and adds the owner-authorized atomic `queue_api.set_staff_access` RPC used by staff editing. Its disposable SQL test passed 17 assertions. It intentionally aborts when existing assignments or reservations violate its constraints; do not apply it until Counter 5 is reconciled and migration 014 is separately approved.

The Add Staff workflow from migration 011 remains available on the retained database. Staff editing through `set_staff_access` requires migration 014. The new cleanup UI remains release-gated until migration 01150 is installed and enabled. No account roles, active cashier assignments, tickets, or MFA factors were changed during this work. The only retained-data change was cancellation of the explicitly selected pending Counter 2 reservation.
